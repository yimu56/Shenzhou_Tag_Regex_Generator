# 标签提取规则生成器

为深舟数据管理平台自动生成「自动标签」正则提取规则的 Windows 桌面客户端。输入一条样例路径与其中需要提取的变量值，一次得到五条候选规则及各自的验证结果，按需选择复制使用。

## 功能特性

- C/S 架构：原生 Windows 桌面客户端，双击 exe 即可使用，无需浏览器、无需启动服务
- 纯 Go 标准库 + lxn/walk 实现，无 CGO，可静态编译为单个 exe
- 一次生成五条候选规则：极简版、边界版、精确版、严格版、定长版
- 定长版按目标字段长度约束提取宽度，避免把相邻的同类型字段一并吞入结果
- 高级模式支持同时提取多个关键词，按输入顺序生成 `sn1`、`sn2`… 多组命名捕获
- 指定样例路径中的任意字段作为目标，自动在测试路径中提取对应位置的字段
- 支持追加多条测试路径，横向比较各规则的泛化能力
- 所有规则均把指定的目标值当作变量处理，而非写死为字面文本
- 同时输出深舟规则（Python re 兼容的字符类）与 JS 验证版（带 `u` flag 的完整正则字面量，可直接粘贴到浏览器控制台）
- 三种引擎分别使用兼容的字符类：本地验证用 Unicode 属性类、深舟用 `[^\W_]`、JS 用 `\p{}` 并附 `u` flag，避免 POSIX 字符类跨引擎失配
- 提供命令行模式，便于脚本调用

## 构建

需要 Go 1.26 及以上版本。`rsrc.syso` 会在编译期自动链接，使控件呈现现代外观并正确支持高 DPI。

### 使用编译脚本（推荐）

Windows 环境下直接双击 `一键编译.bat`，或在项目目录执行：

```bat
一键编译.bat
```

脚本依次完成：检查 Go 环境 → 确认 `rsrc.syso`（缺失时调用 `rsrc` 生成）→ 运行单元测试 → 按脚本顶部的 `VERSION` 参数编译 exe。发布新版本时修改该变量即可。

### 手动编译

```bash
git clone https://github.com/yimu56/shenzhou-tag-regex.git
cd shenzhou-tag-regex

# 生成 manifest 资源（首次或 app.manifest 有改动时执行）
go install github.com/akavel/rsrc@latest
rsrc -manifest app.manifest -arch amd64 -o rsrc.syso

# 静态编译为单个 exe，运行时无控制台窗口
CGO_ENABLED=0 go build -trimpath -ldflags="-H windowsgui -s -w -X main.Version=2.2.0" -o shenzhou-tag-regex.exe .
```

`-H windowsgui` 使程序运行时不创建控制台黑窗口；`-X main.Version=` 用于注入版本号，窗口标题、界面顶部与 `-version` 参数均显示该值，需与脚本顶部的 `VERSION` 保持同步。`rsrc.syso` 已随仓库提供，通常可直接编译。

## 运行

### 桌面客户端（默认）

双击 `shenzhou-tag-regex.exe`，在窗口中填写样例路径、要提取的变量值、测试路径（可选），点击「生成规则」。每条规则附样例与测试路径的验证结果，可一键复制深舟规则或 JS 验证版。勾选「高级模式」后，输入区切换为多关键词输入（每行一个，按路径中出现顺序填写），生成的规则包含 `sn1`、`sn2`… 多组捕获结果。

### 命令行模式

提供 `-path` 或 `-target` 参数时进入命令行模式，不打开窗口。程序无控制台，结果写入当前目录的 `规则结果.txt` 并弹出提示：

```bash
shenzhou-tag-regex.exe -version      # 弹窗显示版本号

shenzhou-tag-regex.exe \
  -path 'E:\AOI追溯\产线3\2026_11_19\7C4E9A21-5B6D-4E8F-9A0C-2D3E4F5A6B7C+LOT20261119008+STATION12_rev2_20261119093015.png' \
  -target 'LOT20261119008+STATION12' \
  -test '测试路径1|测试路径2'
```

`-path`、`-target` 用于命令行模式；`-test` 参数用竖线 `|` 分隔多条测试路径。

## 五条候选规则的差异

核心思路是「字段结构定位」：把目标串中的字段替换为通配类、分隔符原样保留，并按目标在样例中的字段位置计数定位。规则不写死样例中的字母，也不依赖 UUID、`_v3_` 等具体业务结构，正式环境中的字段结构可以完全不同。

| 规则 | 策略 | 适用场景 |
| --- | --- | --- |
| 极简版（推荐） | 字段结构通配 + 宽松结尾 | 绝大多数场景优先尝试 |
| 边界版 | 用目标后紧跟的分隔符锚定右边界 | 目标后直接拼接后缀，需要防止吞并 |
| 精确版 | 匹配到目标字段即止，不强制匹配后续内容 | 需要最短匹配结果 |
| 严格版 | 字段仅限字母数字，排除中文及特殊字符 | 字段名确定不含中文或特殊字符 |
| 定长版 | 每个字段长度与目标一致，只取等宽内容 | 目标后紧跟同类型字段（如日期后接时分秒），需要严格限定提取宽度 |

字段定义为连续的非标点、非符号、非空白字符（含中文）；标点、符号或空白都能作为字段边界，三个引擎的字符类写法不同但口径一致，中文标点同样会被正确识别为边界。定位分隔符由目标在样例中的位置自动识别，并统计其在目标之前出现的次数，因此同一个文件名中不同位置的字段可以分别定位。

## 在深舟中使用

1. 进入管理员平台的标签策略配置，选择自动标签。
2. 正则 key 仅支持英文字符、数字与下划线；中文显示名在检索模板的「自定义名称」中设置。
3. 复制界面中的「深舟规则」，粘贴到正则表达式输入框；普通模式捕获组名固定为 `sn`，高级模式按关键词顺序使用 `sn1`、`sn2`…，对应需要提取的标签值。
4. 在检索模板中验证标签提取结果，必要时改用其他候选规则。

## 测试

```bash
go test ./...
```

测试用例覆盖用户反馈的三组字段定位场景、UUID 尾段、加号分段、后缀吞并、无锚点、定长提取、多关键词高级模式、异常输入等，并确认生成的规则可被 Go 正则引擎正确编译。
